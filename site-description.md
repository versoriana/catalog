**Bibliotheca Manuscripta Versoriana** is a browser-only digital catalog of manuscripts and persons related to Johannes Versoris, built as a set of static files requiring only a standard file server to deploy.

**Technology stack.** The front end is written in vanilla JavaScript and HTML, styled with Bootstrap 5.3 and a small project-specific stylesheet (`versoris.css`). Two third-party libraries handle specialized tasks: CETEIcean (bundled locally) renders TEI-XML as HTML custom elements directly in the browser; MiniSearch provides client-side full-text indexing and search. Bootstrap and MiniSearch are loaded from CDN; there are no build tools, no back-end, and no server-side processing.

**Data model.** All catalog data is encoded in two TEI P5 XML files — `mss.xml` for manuscript records and `PersonRegister.xml` for the person register. These are fetched at page load and processed entirely in the browser. Within `mss.xml`, an authority list of the works ascribed to Versoris is held as a taxonomy (`versoris_opera`) in the teiHeader, and every `msItem` title carries a `@ref` to its canonical work code while keeping the source spelling as its text — the keying that lets witnesses of the same work be grouped despite differing spellings.

**Interface.** The catalog is organized across five pages. The manuscript and person pages each present a sortable, live-filterable table; selecting a row expands an inline detail panel rendered from the corresponding TEI-XML node via CETEIcean behaviors. The opera page offers a work-centred index, inverting the manuscript-first descriptions: it builds the mapping in the browser from the `versoris_opera` taxonomy and the `@ref`-keyed titles, listing each work with the distinct manuscripts that transmit it, every witness linking through to its entry on the manuscript page. The search page offers full-text retrieval across both corpora simultaneously, using a two-pass strategy (exact match boosted over fuzzy) with live autocomplete suggestions, result highlighting, and type filtering between manuscripts and persons. Search state is preserved in the URL query string.

**Deployment.** Because `fetch()` is used to load the XML data files, the catalog requires an HTTP server rather than direct filesystem access, but any static file server — including GitHub Pages — is sufficient.
